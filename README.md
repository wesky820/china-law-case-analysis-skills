# China Law Case Analysis Skills

> 把中国法院的类案裁判方法，编译成 AI 可以调用、普通人也能听懂的法律问答 skills。

这是一套面向中国民商事争议的案由级法律问答 skill 库。它把人民法院案例库入库案例中的裁判规则，拆解为 AI 可以检索和调用的场景模块，帮助用户看清：

- 这件事通常会怎么判断；
- 真正的争议焦点在哪里；
- 哪些事实和证据最关键；
- 可能面临什么风险；
- 下一步可以做什么。

它不是“背法条”的提示词合集，也不代替律师对具体案件出具法律意见。

## 快速开始

```bash
git clone https://github.com/wesky820/china-law-case-analysis-skills.git
cd china-law-case-analysis-skills
```

### 方式一：直接调用已知案由

找到对应目录中的 `SKILL.md`，把它作为 system prompt、项目指令或知识文档使用：

```text
请阅读并遵循「买卖合同纠纷/SKILL.md」回答我的问题。

我的身份：
案件背景：
争议问题：
已有证据：
我想知道：
```

### 方式二：先匹配案由，再调用 skill

不确定案由时，可以让 AI 先在仓库中完成路由：

```text
请先根据我的事实，从本仓库选择最匹配的案由 skill；
如果可能涉及多个案由，请说明主案由和关联案由；
然后按对应 skill 分析事实、证据、风险和下一步。
```

### 方式三：本地检索

```bash
# 查看全部标准 skill
find . -mindepth 2 -maxdepth 2 -name SKILL.md | sort

# 按关键词检索案由、触发场景和裁判规则
rg -l "工程款|优先受偿权" --glob "*.md"
```

这些文档可以接入 ChatGPT、Claude、Gemini、Codex、Cursor、Continue 或自建 Agent，也可以用于法律咨询初筛、类案规则提示、争议焦点梳理和证据准备。

## 工作方式

```mermaid
flowchart LR
  A["用户事实"] --> B["案由识别"]
  B --> C["争点拆解"]
  C --> D["要件事实"]
  D --> E["证据缺口"]
  E --> F["类案规则"]
  F --> G["风险分层"]
  G --> H["下一步行动"]
```

每个标准 skill 尽量遵循同一套回答协议：

1. **结论先行**：先说明大致判断，不让用户先读一页法条。
2. **事实优先**：围绕身份、合同、付款、通知、交付、履行、损害和程序确认关键事实。
3. **证据驱动**：说明要证明什么、现有材料能证明什么、还缺什么。
4. **类案支撑**：在适当位置引用人民法院案例库入库编号和裁判规则。
5. **风险可见**：使用“通常、可能、关键看证据、风险在于”等审慎表达。
6. **行动导向**：落到补证、沟通、发函、协商、仲裁或诉讼前准备。
7. **法源核验**：精确法条、期限、利率、金额、年度标准和地方口径必须核验现行规则。

## 设计原则

### 普通人优先

默认用户不是律师，也不是法官。先让人听懂，再让人能够采取行动。

### 不扮演裁判

不输出“本院认为”式的确定结论，不假装替法院判案，而是解释可能的法律评价、证明对象和裁判风险。

### 不鼓励高风险操作

不建议换锁、断水断电、暴力催收、曝光隐私、伪造证据、倒签合同、剪辑聊天记录、规避法院调查、骗保、虚假鉴定或过激维权。

### 规则必须持续核验

法律、司法解释、地方政策、年度统计数据和裁判口径会更新。交通事故、人身损害、劳动争议、利率、诉讼程序和地方标准尤其需要核验最新官方法源。

### 可复制，也要可迭代

skill 应当能够持续吸收新法源、新案例、新证据形态和真实用户问题，而不是一段长期不变的“万能提示词”。

## 贡献指南

欢迎提交 PR。新增或更新内容时，建议遵守以下规则：

- 新案由使用“案由名称/`SKILL.md`”结构。
- 提交前先检查是否存在同名目录；有同名目录时更新原目录，不再创建重复副本。
- frontmatter 至少包含准确的 `name` 和可用于触发的 `description`。
- 尽量标明规则来源、适用时间和地域背景。
- 不提交未经脱敏的真实姓名、身份证号、电话、住址、聊天记录或案件材料。
- 不只堆法条，要把规则翻译成普通人能理解的判断步骤。
- 对争议问题保留不确定性，不写“必胜”“包赢”“百分百无效”。
- 涉及精确法条、期限、金额或最新政策时，优先核验官方法源。

一个完整的 skill 最好包含：触发场景、回答原则、核心争点、证据清单、常见风险、输出模板和法源核验提醒。
